# Фаза 2 — рабочий каталог и воспроизводимый запуск

> **Для исполнителя:** использовать `superpowers:executing-plans`; выполнять работу непосредственно, с реальными проверками после каждого блока. Не возвращаться к интервью о технических вариантах.

**Goal:** выдать запускаемый локальный проект каталога с проверенными продавцом, покупателем и сотрудником сценариями, инструкцией и архивом без секретов.

**Architecture:** существующий Django/PostgreSQL проект; новый предметный модуль `catalog` использует только публичные интерфейсы identity, access, seller_onboarding и audit. Серверные HTML-формы остаются основой; небольшой собственный JavaScript отвечает за автоматические фильтры, прокрутку и восстановление позиции. Никаких заказов, платежей, публичного сервера или новой внешней инфраструктуры.

**Tech Stack:** текущие закреплённые версии Python/Django/PostgreSQL, Pillow для проверки и безопасного сохранения фотографий, FastEmbed с локальной многоязычной ONNX-моделью для смыслового поиска. Версии новых библиотек фиксируются в pyproject.toml и uv.lock после разрешения зависимостей. Модель поиска не заменяет ведущую модель Hermes и не вызывает платный API.

**Spec:** `docs/superpowers/specs/2026-09-14-phase-2-catalog-design.md`. Все CAT-решения сохраняются, включая общие карточки, смысловой поиск, склады и цифровые черновики.

## Зафиксированные решения реализации

### Права и начальная настройка

- Закрытый каталог: действующая подтверждённая личная учётная запись плюс явный допуск `Participant` в этой установке. Регистрация сама по себе не даёт доступ к каталогу, изображениям или поисковым подсказкам.
- Допуск выдаёт/отзывает существующий `security_admin`; он не выдаёт роль сотрудника или право продавца. Этот же сотрудник управляет справочником, общей карточкой и модерацией через новые узкие полномочия `catalog.read` / `catalog.manage`. Дополнительные роли в эту версию не вводятся.
- Сохраняются действующая сессия, подтверждение почты, блокировки аккаунта, допуск продавца и обязательный TOTP. Управление каталогом сотрудником требует существующей проверки свежего подтверждения входа.
- Учётная запись продавца и служебная учётная запись не смешиваются. Инструкция объясняет первоначальное создание администратора существующим штатным способом, приглашение проверяющего продавцов, регистрацию участника и допуск к каталогу.

### Данные и переходы

- `Category`: название, доступность, версия. `Attribute`: ключ, подпись, категория, обязательность, список допустимых значений; текстовое значение разрешено для характеристики без списка. Все поля имеют явные пределы на внешней границе. Справочник изменяется только сотрудником, предложения продавцов сохраняются отдельно.
- `Product`: UUID, owner UUID / seller UUID (пустые только у общей карточки), kind physical/digital/common, единица pc/kg/m, признак фиксации единицы, черновое содержание, опубликованный снимок, версия черновика и публикации, блокировка сотрудником. Никакой ORM-модели продавца в модуле catalog.
- `Variant`: UUID, продукт, собственная цена и версия цены, снимки характеристик/связей фотографий, состояние draft/published/withdrawn и отдельная блокировка сотрудником. Предложение остаётся тем же вариантом с тем же запасом.
- `StorageLocation`: UUID, продавец, название; `Stock`: вариант + место хранения, точное количество и версия. Одна строка на сочетание варианта и места. Первое место называется «Основное место хранения»; дополнительные создаёт владелец. Остатки разных вариантов/продавцов не объединяются. Покупателю передаётся только наличие.
- Сохранение содержания, добавление варианта и выбор его возврата меняют только общий черновик. Публикация — одна транзакция с проверкой текущих требований для каждого публикуемого/возвращаемого варианта. Неуспешная проверка не меняет прежнюю публикацию.
- Цена и остаток сохраняются отдельно с ожидаемой версией конкретного поля. Строка блокируется на время проверки и записи. Изменение другого поля не вызывает ложного конфликта. При конфликте интерфейс показывает актуальное значение и сохраняет введённое для явного повторения, без автоматической перезаписи.
- Снятие варианта — отдельная операция, сохраняющая количество. Возврат явно помечается в черновике вместе с версией снятия; старый черновик не восстанавливает снятое. Блокировку сотрудника продавец не снимает. Последний снятый вариант скрывает содержание карточки, в отличие от обычного нулевого остатка.
- Цена: RUB, Decimal до двух дробных знаков; количество: целые штуки или Decimal до трёх знаков для кг/м. Ввод принимает обычную десятичную запись с точкой либо запятой, без экспонент, NaN и бесконечности. Пустота не равна нулю; значения отклоняются, если требуют округления. Технический предел — 16 цифр целой части, с понятной ошибкой при превышении. Сохранение нулевой цены также фиксирует единицу.
- Числовые данные не копируются из черновика при публикации. Публикация цифрового товара и приём продаваемого цифрового файла запрещены сервером.

### Фотографии

- Принимаются JPEG, PNG и WebP до 8 MiB и 20 миллионов пикселей, только один кадр. Проверяется декодирование, не одно расширение. Изображение сохраняется заново без EXIF и иных исходных метаданных под серверным UUID; SVG/HTML и произвольные пути не принимаются.
- Загрузчик подтверждает, что это реальное фото соответствующего товара без AI-дорисовок. Проверка файла не выдаётся за доказательство подлинности. Генерации изображений нет.
- `Photo` принадлежит одной карточке; снимок можно связать с несколькими её вариантами. Обложка выбирается отдельно. Публикация проверяет владельца, доступность и хотя бы одно фото каждого публикуемого варианта.
- Файлы хранятся в частном каталоге на постоянном Docker volume; выдаются только через проверяющий права обработчик. Публичный MEDIA_URL не добавляется. Блокировка/отзыв участия учитываются и при запросе прямого URL изображения.
- Нет доступных снимков — согласованная подпись, не чужая галерея. Ошибка загрузки имеет другое сообщение. Фотографии не удаляются необратимо при снятии карточки.

### Общие карточки

- Сотрудник создаёт общую карточку с собственными общими характеристиками и фото. Продавец подаёт запрос на сопоставление опубликованного своего варианта с вариантом общей карточки.
- `MatchRequest` сохраняет конкретные версии содержания, обоснование и решение; `OfferLink` связывает исходный вариант с общим только после проверки сотрудником модели, характеристик, комплектации, состояния и одинаковой единицы. Изменившееся с подачи запроса содержание требует повторной проверки.
- Продавцы подают текстовые предложения об исправлении общей карточки; сами общие данные не меняют. Правка общей идентифицирующей характеристики не может молча подменить товар под уже привязанными предложениями: такие связи требуют нового подтверждения.
- Цены/остатки читаются из исходного предложения, не копируются. Сопоставленные предложения группируются в общей карточке; отклонённый/ожидающий запрос не мешает собственной публикации. В сравнении только доступные предложения в наличии, по текущей цене за одну единицу, с «Доставка ещё не рассчитана».

### Поиск и браузер

- Кандидаты собираются только из опубликованных, разрешённых текущему участнику карточек и вариантов, с действующим допуском продавца и положительным запасом. Поиск/подсказки не получают черновики или точные остатки.
- Нормализация текста: Unicode, регистр, ё/е, слова. Точное совпадение — все слова запроса; совпадения части слов и близкое написание идут ниже с пометкой. Опечатки сравниваются с реальными словами допустимого опубликованного корпуса, не с частным словарём черновиков.
- Смысловая близость: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` через FastEmbed, CPU, 384 компоненты, Apache-2.0 по реестру Qdrant. Официальный реестр указывает около 0,22 GB. Модель загружается один раз в локальное хранилище; после подготовки поиск не требует внешнего API. Реальная смысловая проверка обязательна, нельзя заменить её подставленными векторами и объявить поиск работающим.
- Внутри группы порядок воспроизводим: соответствие запросу, затем опубликованное название и UUID. Одна карточка — один результат, цена только по подходящим предложениям; разные цены показываются через «от…».
- Фильтры: `category` и повторяемые `f.<key>` в URL. ИЛИ внутри ключа; И между ключами на одном варианте. Неизвестные параметры/ключи/значения блокируют поиск с сохранением условий и явным удалением ошибки пользователем. Нулевой результат не является ошибкой параметров.
- Подсказка исправления появляется только при отсутствии точных результатов во всём допустимом наборе и применяется исключительно по нажатию; текущие фильтры сохраняются.
- Порция 20 карточек. Отдельная загрузка HTML-фрагмента вместо нового публичного REST API; отсутствие JavaScript сохраняет обычное открытие HTML и запасную навигацию. Основной режим — автоматическая подгрузка через IntersectionObserver, одна активная загрузка, защита от старого ответа и повторных карточек.
- Ввод текста не отправляет запрос; Enter/«Найти»/изменение фильтра применяют видимый текст. Применённые условия отражаются в URL; копирование не берёт недописанный текст.
- «Назад» использует sessionStorage только для позиции и количества просмотренных результатов, не как разрешение показывать старые данные. При возврате список повторно загружается под текущими правами, затем восстанавливается прежняя/ближайшая позиция. Ошибка сохраняет доступную часть и показывает ошибку, а не конец списка.
- Прямая ссылка выбирает минимальную текущую цену среди доступных вариантов в наличии; из поиска — минимум среди подходящих фильтрам. При равенстве — UUID. Ссылка с `variant` сохраняет именно его. Скрытый вариант не заменяется; закончившийся опубликованный можно смотреть с соответствующей подписью.
