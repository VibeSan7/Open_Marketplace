# Как пользоваться каталогом

Русский | [English](catalog-quickstart-en.md)

Основные команды установки находятся в [README](../../README.md). Здесь — последовательность действий после запуска.

## Аккаунты не нужно смешивать

В этой установке есть три задачи:

- **Администратор безопасности** приглашает сотрудников, разрешает участие и управляет справочником.
- **Проверяющий продавцов** рассматривает заявки продавцов. Эта роль сама по себе не даёт право менять каталог.
- **Личный аккаунт** используется для просмотра и, после одобрения заявки, продажи товаров.

Для локальной проверки используйте отдельные профили браузера или обычное и приватное окна, чтобы не путать входы. Пароли, секрет приложения-аутентификатора и резервные коды не записывайте в проект или отчёт.

## Первый администратор

1. Выполните команду `bootstrap_security_admin` из README.
2. Откройте местную почту: <http://127.0.0.1:8025/>.
3. Откройте письмо-приглашение. Следуйте ссылке именно из письма; не копируйте одноразовую ссылку в публичный чат.
4. Задайте пароль, добавьте запись в приложение-аутентификатор и подтвердите текущий код.
5. Сохраните показанные один раз резервные коды в защищённом месте.
6. Войдите в <http://127.0.0.1:8000/admin/>. Пригласите другого служебного пользователя с ролью `seller_reviewer` — проверяющего продавцов. Приглашённый также завершает настройку через Mailpit.

Если чувствительное действие требует повторного входа, откройте <http://127.0.0.1:8000/security/reauthenticate/>, подтвердите личность и сразу повторите действие. Временную защиту не нужно отключать.

## Подготовить личный аккаунт продавца

1. Откройте <http://127.0.0.1:8000/register/>, зарегистрируйте отдельный личный аккаунт.
2. Подтвердите почту ссылкой из Mailpit и войдите.
3. В разделе <http://127.0.0.1:8000/security/> включите двухэтапную защиту.
4. Откройте <http://127.0.0.1:8000/seller/applications/create/>, заполните и отправьте заявку продавца.
5. В другом окне войдите проверяющим, откройте очередь заявок в панели сотрудников, начните рассмотрение и одобрите заявку.
6. Администратор открывает <http://127.0.0.1:8000/catalog/manage/>, вводит email продавца, отмечает разрешение участия и сохраняет.

Допуск к каталогу не заменяет одобрение продавца. Для покупателя достаточно подтверждённого личного аккаунта и разрешённого участия; заявку продавца ему подавать не надо.

## Создать категорию

В управлении каталогом создайте категорию, например «Одежда». Добавьте характеристики: «Цвет», «Размер», при необходимости «Материал».

- Стабильный ключ — короткое внутреннее имя: `color`, `size`, `material`. Если его оставить пустым, он создаётся из названия. После появления товаров не меняйте ключ без необходимости.
- Для выбора из списка впишите значения по одному в строке. Пустой список разрешает свободный текст.
- Галочка обязательности проверяется при публикации. Неполный черновик сохранять можно.
- Новое обязательное описательное поле проверяется при следующей публикации содержания; оно не отменяет отдельное сохранение цены или остатка.

## Добавить первый товар

1. Продавец открывает <http://127.0.0.1:8000/catalog/own/>, нажимает «Создать карточку».
2. Выбирает физический товар и единицу: штуки, килограммы или метры.
3. Вводит название, описание, категорию и сохраняет черновик. После выбора категории появляются её характеристики.
4. Загружает настоящие фотографии и подтверждает их происхождение. Допустимы JPEG, PNG и WebP; файл проверяется и сохраняется без исходных метаданных.
5. Создаёт вариант, например «Красный S», заполняет его характеристики и отмечает фотографии именно этого варианта.
6. Отдельно сохраняет цену и остаток. Пустое поле не равно нулю. Для бесплатного товара укажите `0`; для отсутствующего запаса — `0`.
7. Нажимает «Опубликовать». Если чего-то не хватает, исправляет указанную ошибку и повторяет публикацию.
8. Открывает каталог и проверяет карточку. Товар с нулевым запасом не попадает в поиск, но опубликованное описание остаётся доступным по прямой ссылке.

Общие характеристики карточки должны быть одинаковы у всех вариантов. Цвет и размер обычно указываются у вариантов, а не одновременно в общей части и противоречащем ей варианте.

После первого сохранения цены или количества единица фиксируется. Чтобы продавать в другой единице, создайте другую карточку. Дробная цена — до копеек; килограммы и метры — до тысячной; штуки — целые. Значения, требующие округления, отклоняются.

## Изменить, снять и вернуть

- Измените содержание и сохраните черновик. Покупатель по-прежнему видит прежнюю опубликованную версию.
- «Опубликовать» проверяет весь публикуемый набор. Частичная публикация при ошибке не выполняется.
- Цена и остаток сохраняются сразу отдельными кнопками. Старый черновик их не откатывает.
- Если другой ввод уже изменил значение, появится конфликт: сравните актуальное значение с сохранённым в форме вводом и подтвердите повторную запись явно.
- «Снять вариант» и «Снять всю карточку» действуют сразу, но не удаляют фотографии и количество.
- Для возвращения снятого варианта отметьте явный возврат, сохраните вариант и опубликуйте карточку. Это не снимает блокировку сотрудника.
- Дополнительное место хранения создаётся в редакторе; его остаток заполняется отдельно для каждого нужного варианта.

## Общая карточка и сравнение предложений

Администратор создаёт общую карточку через «Мои карточки»: общие описание, категория, характеристики, варианты и фотографии. Цены и запасы в ней не вводятся — они берутся из предложений продавцов.

Продавец в редакторе своего опубликованного варианта выбирает соответствующий общий вариант и отправляет обоснование совпадения. Выбор возможен и до появления первого предложения общей карточки.

Сотрудник проверяет модель, характеристики, комплектацию, состояние и единицу. Только после его явного подтверждения предложение попадает в общую карточку. Смысловой поиск не подтверждает идентичность. Изменение идентифицирующих данных требует нового подтверждения связи.

Предложения в наличии сравниваются по цене за одинаковую единицу. Надпись «Доставка ещё не рассчитана» означает, что это не окончательная стоимость покупки. Покупки в этой версии нет.

## Поиск и ссылки

- Печатайте запрос и нажмите Enter или «Найти». Сам набор текста поиск не запускает.
- Изменение фильтра сразу применяет и фильтр, и текст, который сейчас набран.
- Несколько значений одной характеристики означают «или», разные характеристики должны подходить одному варианту товара.
- Серые значения сейчас не дают подходящих товаров. Уже выбранное недоступное значение не снимается автоматически.
- Сначала идут точные результаты, затем помеченные приблизительные. Подсказка исправления запроса применяется только по нажатию и сохраняет фильтры.
- Прокрутка загружает следующие карточки. При ошибке нажмите «Повторить»; уже загруженная часть не должна исчезать.
- «Поделиться условиями поиска» копирует применённые условия, а не недописанный текст.
- Ссылка на вариант сохраняет выбранный вариант, но не старую цену и не право доступа. Она не покупает и не резервирует товар.
- Ссылки с `127.0.0.1` работают только на том же компьютере. Для другого компьютера нужен отдельно настроенный сервер; пересылка локальной ссылки его не создаёт.

## Резервная копия и обновление

База и фотографии хранятся раздельно. Для восстановления нужны **база + фотографии + исходный `.env`**. Без прежних ключей зашифрованные данные нельзя считать восстановленными. Модель поиска можно скачать заново.

Команды ниже относятся к вашей локальной установке. Копия содержит чувствительные данные; храните её вне публичных облачных папок, с ограничением доступа и шифрованием на выбранном носителе. Папка `backups/` исключена из Git и Docker-образа.

На время согласованной копии остановите запись через приложение:

```bash
docker compose stop web worker
```

```bash
mkdir -p backups
```

```bash
docker compose exec -T postgres sh -c 'pg_dump --username "$POSTGRES_USER" --dbname "$POSTGRES_DB" --format=custom' > backups/catalog.dump
```

```bash
docker compose run --rm --no-deps -T web tar -czf - -C /app/private-media . > backups/photos.tar.gz
```

```bash
cp -p .env backups/.env
```

```bash
docker compose up -d
```

Не публикуйте эту папку и не загружайте её как артефакт GitHub. Перенесите копию в защищённое хранилище. Не считайте команду копирования доказательством восстановления: проверьте копию в отдельной установке, не поверх единственной рабочей базы.

Перед обновлением сохраните проверенную копию. Обновляйте код в той же папке с прежним `.env` и именем проекта Docker, затем выполните миграции и пересоберите приложение командами из README. Если что-то пошло не так, остановите новую версию и восстанавливайте **согласованный комплект** в отдельной среде. Не пытайтесь вернуть прежние ключи поверх новой базы или удалять хранилища наугад.

## Если что-то не работает

- **Docker не отвечает:** запустите Docker Desktop, дождитесь готовности и повторите команду.
- **Порт занят:** другая программа уже использует 8000, 8025 или 1025. Не останавливайте чужой проект вслепую. Настройте отдельные порты своей копии вместе с `APP_BASE_URL` в `.env`.
- **Модель не подготовлена:** повторите `docker compose run --rm web python manage.py prepare_catalog_search`; интернет нужен для загрузки, не для обычного поиска после неё.
- **Письмо не пришло:** проверьте `docker compose ps`, затем запустите один проход доставщика: `docker compose run --rm web python manage.py run_outbox_worker --once`. Смотрите местную почту Mailpit, а не внешний ящик.
- **Нет доступа к каталогу:** подтвердите почту, проверьте допуск участника у администратора. Для редактора дополнительно нужны активный продавец и двухэтапная защита.
- **Нет товаров:** новая установка пустая; опубликованные варианты с нулевым запасом в поиск не входят.
- **Повторная проверка личности:** откройте раздел подтверждения входа и повторите действие сразу после подтверждения.
