# Тестовые заказы

Тестовый заказ — реальные деньги не списываются. Функция предназначена только для демонстрации пользовательского пути: выбор опубликованного физического предложения, симулированная оплата, передача и завершение.

## Включение

Функция выключена по умолчанию. В файле `.env` локальной Docker-установки замените `DEMO_ORDERS_ENABLED=false` на `DEMO_ORDERS_ENABLED=true`. Пересоздайте только веб-службу (не удаляйте тома с данными):

```sh
docker compose build web
```

```sh
docker compose run --rm --no-deps web python manage.py migrate --noinput
```

```sh
docker compose up -d --no-deps web
```

Любое другое значение переменной, включая отсутствие переменной, оставляет маршруты `/demo-orders/` недоступными с ответом 404. Страница `/cart/` объясняет, что демонстрация выключена, и не разрешает оформление. Платёжных API, SMTP, адресов доставки и реальной выдачи в этом потоке нет.

## Сценарий

1. Войдите активной личной учётной записью с подтверждённой почтой. Допуск нужен для закрытых товаров, но не для публичных.
2. Добавьте выбранные варианты в `/cart/` и оформите корзину либо откройте одиночное тестовое оформление из карточки. В корзине новая цена требует подтверждения обновлением строки; оформление всех строк атомарное и защищено от дубликатов.
3. Укажите количество и отправьте форму. Сервер создаёт заказ по UUID intent_id, рассчитывает сумму в рублях и резервирует отдельный симулированный остаток.
4. Выберите успешную оплату или отказ. Отказ оставляет заказ в ожидании и позволяет повторить успех.
5. Действующий владелец предложения может симулировать передачу, покупатель — завершение. Покупатель или действующий владелец могут отменить заказ до передачи.

Снимок названия, варианта, продавца, единицы, цены, количества и суммы сохраняется в заказе и не меняется после редактирования каталога. Симулированный остаток один раз инициализируется суммой известных положительных остатков каталога; последующие изменения каталога его не пополняют и не превращают в реальную защиту от oversell (перепродажи сверх наличия).

## Проверка

Интеграционные тесты находятся в `open_marketplace.catalog.tests.test_demo_orders`, `test_demo_order_concurrency` и `open_marketplace.web.tests.test_demo_journey`; полный браузерный сценарий — в `catalog.tests.test_browser`. Их запускают с отдельной тестовой базой. Для теста конкурентных запросов нужен PostgreSQL; TestCase не доказывает реальные блокировки, поэтому concurrency-тесты используют TransactionTestCase и отдельные соединения.
