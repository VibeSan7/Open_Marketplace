# Первоначальная установка

Эта инструкция относится к новой локальной копии Open Marketplace. Она не подключается к чужой установке, не меняет текущую демонстрацию и не заменяет настройки существующей базы.

После запуска откройте в браузере [встроенную read-only инструкцию](http://127.0.0.1:8000/setup/). Она показывает тот же безопасный порядок действий и поясняет границы публичного просмотра и закрытых данных.

## 1. Получите исходный код

Скачайте ZIP текущей ветки или клонируйте репозиторий. Перейдите в папку, где находится `compose.yaml`; все команды ниже выполняются из неё. Публичная загрузка исходников не даёт доступа к чужим аккаунтам, данным или серверу.

## 2. Создайте настройки один раз

Используйте Python-блок генерации из раздела [README о настройках](../../README.md#3-создать-настройки--только-при-первом-запуске). Он создаёт новый `.env`, не выводит секреты и отказывается перезаписывать существующий файл. Не удаляйте `.env` для уже работающей базы и никогда не отправляйте его содержимое в чат или журнал.

## 3. Запустите приложение

```bash
docker compose run --rm --build web python manage.py migrate --noinput
```

```bash
docker compose run --rm web python manage.py prepare_catalog_search
```

```bash
docker compose up --build -d
```

Сайт откройте по адресу <http://127.0.0.1:8000/>, а локальную почту — в [Mailpit](http://127.0.0.1:8025/). `localhost` и `127.0.0.1` означают только компьютер, на котором запущен Docker; это не публикация в интернете.

## 4. Пройдите защищённую настройку

После миграций выполните существующую одноразовую команду:

```bash
docker compose run --rm web python manage.py bootstrap_security_admin --email admin@example.test
```

Откройте приглашение в Mailpit, задайте пароль, настройте приложение-аутентификатор и сохраните резервные коды вне репозитория. Не обходите приглашение, двухэтапную защиту или повторную проверку личности. Для следующих шагов используйте отдельные личные и служебные аккаунты.

## 5. Границы демонстрации

Гости видят только явно открытые опубликованные товары. Для избранного и тестовых заказов публичных товаров нужен активный личный аккаунт с подтверждённой почтой, а для закрытых товаров — ещё и допуск. Продажа и управление не разрешаются регистрацией автоматически: администратор допускает продавца по email. Для быстрого знакомства есть [отдельное учебное наполнение](storefront-demo-ru.md).

В этой версии нет реальных заказов, платежей, резервирования, доставки или выдачи цифровых товаров. Отдельный [тестовый сценарий](demo-orders-ru.md) позволяет проверить симуляцию оплаты, передачи и отмены без реальных денег. Локальный запуск — демонстрация на вашем компьютере, а не готовый публичный сервис.
