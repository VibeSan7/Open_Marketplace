## Local verification

- Full suite: **647 tests, OK**. It includes Chromium browser flows, guest permissions, email verification, private listings/photos, the cart, fractional quantities, duplicate submissions and concurrent actions.
- `manage.py check` reported no issues; `makemigrations --check --dry-run` found no unrecorded schema changes; **all 12 module-boundary contracts passed**.
- A separate empty Docker installation exercised migrations, search preparation and web/worker startup. The import created **24 products, 48 variants, 6 categories, 3 fictional stores and 24 photos**. Repeating the import created no duplicates.
- Restore verification: the database was exported with `pg_dump` and photos were transferred as an archive. Accounts, roles, a seller application, decision history, events, a listing, variant, permissions and a photo were checked in a different database. Both checks passed.
- Live guest storefront: viewport widths of **360, 390, 768 and 1440 px**, with no page-level horizontal overflow or JavaScript errors. At the mobile size, the first product card starts approximately **483 px** from the top. Horizontal scrolling within the category strip is intentional.
- All **24 product pages** were visited in mobile and desktop Chromium: **48 page checks and 96 variant-selection checks**. Photos loaded; guests were not shown an add-to-cart form without signing in.
- Licenses and authorship for all **24 photos** were checked against Wikimedia Commons; local SHA-256 values and attribution were verified. Photos are illustrations; educational names, prices and configurations are not real offers.
- Gitleaks scanned the prepared source and Git history with no findings. `.env`, working databases, backups, test artifacts and personal data are not included in the source archive.

Verified storefront screenshot: [desktop](../images/storefront-preview.png). Installation commands are in the [README](../../README.md); import and rollback instructions are in the [guide](../runbooks/storefront-demo-en.md).

## Final verification after the local demo upgrade

- The final browser report is complete: at **390 and 1440 px**, exactly **24 public products** were available, with no JavaScript errors or page-level horizontal overflow.
- **18 URLs for older private listings and photos** were checked over HTTP: guest access was denied. Existing records, photos and the original `.env` were preserved; a backup was restored and verified separately.
- A guest opening `/cart/` receives the correct **HTTP 303** redirect to `/login/?next=/cart/`. The initial expectation of HTTP 302 was a test-harness mistake, not an application error; the scenario was corrected and passed.
- This verifies the agreed local demonstration at `127.0.0.1:8000`, not an internet deployment. The working database, private URLs, settings and backups are not included in the repository.

## Limitations

This is a locally runnable project, not an internet-hosted store. Payments and order handover are simulations; real payment, shipping and commerce integrations are not connected. Chromium checks do not amount to verification in every browser or on physical phones. No source-code license has been separately granted; code-use terms and third-party image licenses are distinguished in [code-use-status](../code-use-status.md).

Check GitHub for the CI status and exact commit of the published PR/tag; this document does not replace CI results.
