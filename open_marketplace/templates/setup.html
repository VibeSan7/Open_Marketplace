Локальная демонстрация

Настройка Open Marketplace

Эта инструкция ничего не создаёт и не меняет в базе. Новая копия начинается без товаров и готовых учётных записей.

1. Запустите свою копию

Скачайте исходный код, создайте настройки по README и запустите Docker Compose. Для локальной почты используется Mailpit: это почтовый ящик вашей копии, а не настоящая отправка на внешний адрес.

localhost и адрес 127.0.0.1 означают компьютер, на котором запущен Docker. Такая ссылка не открывает сайт на другом компьютере и сама не публикует его в интернете.

2. Создайте первого администратора безопасности

После миграций выполните существующую одноразовую команду. Она создаёт только приглашение; публичной формы регистрации администратора нет.

docker compose run --rm web python manage.py bootstrap_security_admin --email admin@example.test

Откройте приглашение в Mailpit, задайте пароль и настройте приложение-аутентификатор. Резервные коды показываются один раз. Не помещайте пароли, секреты TOTP, коды восстановления или содержимое .env в чат, репозиторий и журналы.

Панель сотрудников предназначена для уже приглашённых служебных аккаунтов.

3. Разделите роли и допуск

  1. Администратор приглашает проверяющего продавцов через панель сотрудников.
  2. Создайте отдельный личный аккаунт через регистрацию, подтвердите письмо в Mailpit и выполните вход.
  3. Для продаж включите двухэтапную защиту в разделе безопасности аккаунта. Для просмотра товаров покупателем она необязательна.
  4. Для продажи откройте инструкцию продавца, заполните тестовую заявку и дождитесь проверки.
  5. В управлении каталогом администратор создаёт категории и их характеристики, затем явно разрешает участие личному аккаунту по его email. Одной регистрации или одобрения заявки продавца недостаточно.

4. Добавьте искусственные демонстрационные данные

Продавец создаёт карточку и добавляет безопасные тестовые описания, фотографии, цену и остаток, затем публикует её. Покупатель открывает каталог после подтверждения почты и явного допуска.

В этой версии нет реального checkout, оплаты у провайдера, расчёта доставки или выдачи цифровых товаров. Локальные резервы, заказы и план физической отгрузки существуют отдельно и не означают, что установка настроена для торговли или доступна в интернете.
